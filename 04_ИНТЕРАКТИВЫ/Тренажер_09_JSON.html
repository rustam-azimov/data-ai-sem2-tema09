Разбери ответ API

Сначала исследуйте ответ сервиса. Затем превратите вложенные данные в таблицы и проверьте, что не потеряли товары и не исказили расчёт.

1. Что именно загрузилось?

Встроенный снимок содержит первые 30 товаров API. Для упражнений со страницами это отдельный каталог из 30 товаров. В исходном ответе API total — : снимок не является всем каталогом.

Поиск считает совпадения текста. Для подсчёта товаров убедитесь, что найденный id принадлежит объекту в массиве products, а не вложенному объекту.
Сколько товаров вернулось на этой странице?

3. Что означает одна строка?
Как сверить прогноз по исходным массивам reviews?
Найдите reviews в каждом документе и посчитайте элементы массива. Ниже — сверка длин этих массивов: число строк после раскрытия равно их сумме.
Раскрытие здесь сохраняет только пары «товар–отзыв», как $unwind без preserveNullAndEmptyArrays. Товар без отзывов не даёт ни одной строки. Средняя цена по таким строкам придаёт больший вес товарам с большим числом отзывов.


4. Соберите две связанные таблицы
products: одна строка — один товар. reviews: одна строка — один отзыв; product_id ссылается на products.id. Поля tags и dimensions сохраняем в products как JSON-строки; потерять их при переходе в CSV нельзя. brand_state отличает отсутствующий ключ от null.
Какие поля сохраняются?
Для текущих задач: id, title, category, price, stock, dimensions_width, brand, brand_state, tags_json, dimensions_json; для отзывов — product_id, review_index (индекс внутри массива, начиная с 0), rating, comment, date, reviewerName, verified, verified_state. Для остальных полей CSV пустая ячейка может соответствовать missing, null или пустой строке; различия сохраняет исходный JSON. Другие поля исходного API остаются в исходном JSON. Это аналитическая проекция, а не обратимое преобразование всего ответа API.


5. Проверьте вывод ИИ
«После раскрытия reviews число строк выросло. Это просто другой формат, поэтому средняя цена не изменится, а товары без отзывов всё равно останутся».
